# Trustworthy Local Document Intelligence — Stage 1

A local, **fully-offline** system on an Apple M1 (8GB unified memory) that:
- (a) answers questions over 16 long documents containing numeric tables, and
- (b) verifies factual claims against those documents.

Numbers are never generated by the LLM — every numeric answer is **computed in Python** against
structured table data, with a citation back to `{doc, page, table_id, cell}`. The model only
selects which cells and which operation.

**Status: Phases 0–4 complete** (deliverables 1A, 1B, 1C). Phase 5 (quantization ladder, 1D) and
Phase 6 (memo) are not started.

---

## 1. Setup

The system default `python3` on this machine is 3.7, which is too old for `mlx-lm` (needs ≥3.9).
Use a dedicated env:

```bash
conda create -n doc-intel python=3.11
conda activate doc-intel
pip install -r requirements.txt
```

Check Metal is visible to MLX (expect `Device(gpu, 0)`):

```bash
python -c "import mlx.core as mx; print(mx.default_device())"
```

Pre-download the model once (this is the only step that needs network):

```bash
python -c "from mlx_lm import load; load('mlx-community/Qwen2.5-7B-Instruct-4bit')"
```

## 2. Build the corpus and index

```bash
python download_corpus.py          # fetches 16 public PDFs into corpus/ (~39MB)
python -m src.ingest.run_ingest    # PDFs -> SQLite + FAISS indices  (~20 min on M1)
```

`run_ingest` does four things in order: extracts prose chunks and tables, repairs tables with
dropped row labels, verifies stored cells against the source page text, then builds the prose and
table retrieval indices. It writes `results/ingestion_check.md`.

Everything after this point runs **with the network off**. To prove it, prefix any command with
`HF_HUB_OFFLINE=1` — that makes `huggingface_hub` refuse all network calls:

```bash
HF_HUB_OFFLINE=1 python -m src.qa.ask "..."
```

## 3. Run each deliverable

### 1A — Ask a question

```bash
HF_HUB_OFFLINE=1 python -m src.qa.ask "What was the noncurrent loan rate for construction and development loans at all insured institutions?"
```

Expected output — note the number is computed, not generated, and the citation resolves to a cell:

```
A: 0.6
   (computed in Python: operation=lookup)
path: numeric  |  confidence: 0.689
citations:
  - fdic_quarterly_banking_profile_2024q1 p13 p13_t0 r23c1
```

Options: `--json` for machine-readable output, `--no-llm-router` for deterministic rules-only
routing (used for the Phase 5 ladder so routing noise doesn't confound the comparison).

Try all three paths:

```bash
# prose
HF_HUB_OFFLINE=1 python -m src.qa.ask "By how much did real GDP increase in the first quarter of 2024?"
# numeric
HF_HUB_OFFLINE=1 python -m src.qa.ask "What percent of credit card loans were noncurrent at all insured institutions?"
# multi-doc
HF_HUB_OFFLINE=1 python -m src.qa.ask "Compare the homeownership rate with the official poverty rate."
```

Each numeric question takes **~35–50s** on this M1 at INT4. That is expected; the eval is about
methodology, not speed.

### 1B — Gold set and planted-error summary

- `gold_set.json` — 20 questions (8 prose, 8 numeric, 4 multi-doc) with expected answers and
  citations. Every expected answer was read from the **source PDF**, not from the store.
- `summary.md` — 15 analyst claims, 6 of which are deliberately wrong.
- `answer_key.enc` — encrypted key. The plaintext (`answer_key.json`) and the Fernet secret
  (`.answer_key_secret`) are gitignored and never committed.

Inspect the key (needs `.answer_key_secret` present):

```bash
python -m src.verify.keystore decrypt answer_key.enc
```

Regenerate the encrypted key after editing the plaintext:

```bash
python -m src.verify.keystore encrypt answer_key.json answer_key.enc
```

### 1C — Verification layer

```bash
HF_HUB_OFFLINE=1 python -m src.verify.score
```

Verifies all 15 claims, decrypts the key at eval time, and writes
`results/verification_report.md` (precision/recall with the positive class stated, a 3-way
confusion matrix, per-claim results) plus `results/verification_raw.json`.

To run verification without scoring:

```bash
HF_HUB_OFFLINE=1 python -m src.verify.verify
```

## 4. Test / sanity-check

There is no pytest suite; checks are runnable one-liners against real data.

```bash
# the compute layer refuses bad plans instead of guessing
python -c "
import sqlite3
from src.ingest.db import SCHEMA
from src.qa.compute import CellRef, execute_plan, ComputeError
c=sqlite3.connect(':memory:'); c.executescript(SCHEMA)
c.execute(\"INSERT INTO tables VALUES ('d',1,'t',1,1,'100',NULL,'h')\")
c.execute(\"INSERT INTO tables VALUES ('d',1,'t',1,2,'150',NULL,'h')\")
r=execute_plan(c,'pct_change',[CellRef('d','t',1,1),CellRef('d','t',1,2)])
print('pct_change 100->150 =', r.value)
try: execute_plan(c,'lookup',[CellRef('d','t',9,9)])
except ComputeError as e: print('missing cell refused:', e)
"

# gold-set numeric answers still reconcile against the store
python -c "
import json,sqlite3
from src.qa.table_index import list_numeric_cells
conn=sqlite3.connect('index/doc_store.sqlite')
cells=list_numeric_cells(conn,'fdic_quarterly_banking_profile_2024q1','p12_t0',limit=500)
m={(c['section'],c['row_label'],c['col']):c['value'] for c in cells}
print('noncurrent C&D =', [v for k,v in m.items() if 'Noncurrent' in k[0] and k[1].startswith('Construction') and k[2]==1])
"

# ingestion honesty: what broke and what was repaired
grep -c "INCOMPLETE:" results/ingestion_check.md   # rows still holding values with no label
grep -c "REPAIRED:"   results/ingestion_check.md   # tables rebuilt from page words

# the plaintext key and secret must NEVER be committable
git check-ignore -v answer_key.json .answer_key_secret
```

## 5. Repo map

```
download_corpus.py            16 verified PDF URLs + fetch with retry/verification
src/ingest/
  db.py                       SQLite schema (tables, chunks, documents, suspect_cells)
  parse_cell.py               cell -> (value, unit); strips footnote markers
  tables.py                   pdfplumber extraction + label-loss repair pass
  prose.py                    PyMuPDF page-anchored chunking
  embed.py                    bge-small-en-v1.5 + FAISS prose index
  verify_cells.py             verifies stored cells against source page text
  run_ingest.py               orchestrator -> results/ingestion_check.md
src/qa/
  llm.py compute.py plan.py router.py table_index.py answer.py ask.py
src/verify/
  keystore.py                 Fernet encrypt/decrypt for the answer key
  candidates.py               gold-set candidate proposal (quality-gated)
  verify.py                   claim -> verdict + citation + confidence
  score.py                    precision/recall + 3-way confusion matrix -> 1C report
results/
  phase0_offline_proof.md     offline load proof, tok/s, peak memory
  ingestion_check.md          per-doc stats, sample tables, full breakage log
  known_limitations.md        L1-L6, durable record for the memo
  verification_report.md      deliverable 1C
```

Not committed (rebuildable or secret): `corpus/*.pdf`, `index/`, model weights,
`answer_key.json`, `.answer_key_secret`.

## 6. Known limitations

Read `results/known_limitations.md` before trusting any number this system produces. The
important one:

> **The confidence score measures auditability, not correctness.** It is computed from retrieval
> similarity and which code path ran — never from whether the answer is right. Observed directly:
> one answer scored **0.753 while being wrong**, and after the fix the same question scored
> **0.689 while being right**. Do not read it as a correctness probability.

Also documented there: label loss (repaired, with logged residue), number splits across columns
(detected and suppressed), merged multi-number cells (fail safe), units living in headers rather
than cells, and the classes of silent partial extraction the breakage log still cannot see.
